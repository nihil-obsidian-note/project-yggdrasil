## 설정 문서 작성·수정 사전 읽기

`설정` 문서를 새로 작성하거나 수정하기 전에는 반드시 프로젝트 설정 루트의 [문서 작성 및 수정 지침](../문서 작성 및 수정 지침.md)을 먼저 읽고 따른다. 해당 문서는 본문 형식·문단·표현·사후 점검의 기본 규칙이며, 이 문서는 룩스테라 고유의 메타데이터와 분류 기준을 보완한다.

`인덱스`는 여러 국가·도시국가·부족국가·연맹의 체제와 관계를 횡단해 찾는 기준 문서군이다. 정치 체제나 대륙별 세력 구도를 다룰 때에는 먼저 해당 인덱스를 확인하되, 인덱스의 요약으로 개별 정본의 세부 사실을 덮어쓰지 않는다.

`라이브러리`는 여러 정본 문서에 반복 적용할 수 있는 분류 체계·조립 규칙·제작 질문을 보관하는 문서군이다. 라이브러리는 설정 사실을 새로 확정하는 정본이 아니며, 개별 설정 문서나 세력 관계 문서와 충돌할 경우 개별 정본을 우선하고 라이브러리를 후속 갱신한다. 정치체제·국가 통치·항구 주권 작업에는 [정치체제 라이브러리](라이브러리/정치체제 라이브러리.md)를 사용한다. 용종의 별칭·고유명·아종·지역 변종 이름을 만들거나 점검할 때에는 [용종 명명 라이브러리](라이브러리/용종 명명 라이브러리.md)를 사용한다.

## 폴더 구조

- `비밀 설정`: 아직 공개 전인 설정
- `설정`: 공개된 설정. 일반 문서는 `설정/<type>/`에 둔다. `region: 청연` 문서는 지역을 우선하여 `설정/청연/<type>/`에 둔다. 문서명으로 찾을 때에는 `설정` 아래를 재귀 검색하며, 파일명·YAML·내부 위키 링크는 이관만으로 바꾸지 않는다.
- `신격`: 공개된 신격 정보
- `용종 도감`: 룩스테라 용종 개체의 정식 설정 문서
- `이미지`: 설정 문서가 참조하는 정식 이미지 자료
- `이미지/용종 도감`: 용종 문서의 썸네일과 본문 이미지가 참조하는 정식 이미지 폴더
- `템플릿`: 설정 양식
- `설정 정비`: 문제 발견부터 변경 계획, 정본 적용, 검증, 완료 이력까지 관리하는 작업 문서군. 진입점은 `설정 정비/설정 정비 현황.md`이며, 새 작업 전에는 같은 대상·고유명사·문제의 기존 작업을 확인한다.
- `인덱스`: 여러 정본 문서를 횡단해 비교·탐색하는 정리 문서
- `라이브러리`: 정본에서 추출한 재사용 가능한 분류 체계·조립 규칙·제작 질문
- `스토리 설계`: 이야기 전개와 사건 설계
- `세력 관계`: 세력, 인물, 단체 사이의 관계

템플릿 파일명은 `설정_기본 템플릿`, `설정_국가 템플릿`, `신격_기본 템플릿`처럼 분류와 대상을 드러내는 형식을 사용한다.

## 용종 이미지 경로 규칙

`TRPG 데이터/14. 용종 이미지`는 용종 이미지를 생성하거나 수집한 뒤 유형별로 보관하는 작업용 저장소다. 이 폴더는 룩스테라 설정 문서가 참조하는 정식 이미지 폴더가 아니다.

룩스테라의 용종 문서는 프론트매터 `thumbnail`, Obsidian 이미지 임베드, Markdown 이미지 링크와 그 밖의 이미지 참조에 아래 경로만 사용한다.

```text
프로젝트 위그드라실/룩스테라/이미지/용종 도감/<파일명>
```

```yaml
thumbnail: '프로젝트 위그드라실/룩스테라/이미지/용종 도감/<파일명>'
```

```md
![[프로젝트 위그드라실/룩스테라/이미지/용종 도감/<파일명>]]
```

- 용종 문서에 `TRPG 데이터/14. 용종 이미지`, `14. 용종 이미지` 또는 그 하위 경로를 기록하지 않는다.
- 보관 폴더의 이미지를 문서에 사용할 때에는 먼저 `이미지/용종 도감`에 같은 파일을 배치한다.
- 문서에 경로를 기록하기 전에 `이미지/용종 도감`의 실제 파일명과 확장자를 확인한다.
- 정식 폴더에 파일이 없으면 보관 경로를 대신 참조하거나 존재하지 않는 파일명을 추정하지 않는다. 누락 파일과 필요한 복사·이동 작업을 보고한다.
- 기존 용종 문서를 수정할 때에는 `thumbnail`과 본문 전체의 이미지 임베드를 함께 점검한다.

## 공통 메타데이터

새 문서는 YAML 프론트매터를 기본으로 사용한다.

- `uuid`: 제목·파일명·링크가 바뀌어도 유지하는 고유 식별자
- `title`: 공통 제목 키. `이름`을 사용하지 않는다.
- `docType`: 문서군 판별값
- `thumbnail`: 값이 없으면 반드시 `''`
- `status`: 문서 진행 상태
- `created_at`: 자동 생성 항목
- `updated_at`: 자동 갱신 항목

기본 `docType`은 `setting`, `deity`, `secret_setting`, `relation`, `story_design`, `maintenance`, `template`을 사용한다.

## 템플릿 문서

템플릿은 신규 문서 작성의 기준 원본이다. YAML 프론트매터에 `title`, `uuid`, `docType: template`, `thumbnail: ''`, `status`, `created_at`, `updated_at`을 포함한다.

설정 계열 템플릿은 필요에 따라 `type`, `subtype`, `region`을 함께 둔다. 빈 값은 `-`가 아니라 반드시 `''`로 기록한다.

`type: 도시국가`, `subtype: 항구` 문서는 [설정_항구 템플릿](템플릿/설정_항구 템플릿.md)을 사용한다. 항구가 아닌 도시국가 문서는 [설정_도시국가 템플릿](템플릿/설정_도시국가 템플릿.md)을 사용한다. 도시국가와 항구는 국가 템플릿에 억지로 맞추지 않으며, 설립 주체·현재 주권자·후원·보호 세력·주권 상태·통치체제·생존 기능을 구분한다.

대륙보다 작은 자연 공간과 초자연적 환경을 독립 문서로 작성할 때에는 [설정_지형 템플릿](템플릿/설정_지형 템플릿.md)을 사용한다. 대륙 전체는 기존 [설정_대륙 템플릿](템플릿/설정_대륙 템플릿.md)을 유지하며, 도시·마을·조사 거점은 지형 안에 있더라도 도시 템플릿으로 분리한다.

### 지형 문서

- 대륙보다 작은 숲·사막·산맥·협곡·지하 생태권·수계·변칙 공간은 `type: 지형`으로 작성하고 [설정_지형 템플릿](템플릿/설정_지형 템플릿.md)을 적용한다.
- `subtype`은 복합 특징을 모두 나열하지 않고 형태상 가장 대표적인 하나를 사용한다. 바다피는 협곡은 `협곡`, 죽은 숨 아래는 `지하`처럼 기록하며, 독기·산호·약한 중력·용성 순환 같은 횡단 특징은 본문이나 태그 체계에서 다룬다.
- 필수 본문 골격은 `개요`, `위치와 범위`, `지형 구조와 환경`, `생태와 생활권`, `이동과 위험`, `항목`, `요약`이다. `내부 지형 요소`, `형성과 변화`, `자원과 이용`, `역사적 흔적`은 독립적인 내용을 실제로 보유할 때만 추가한다.
- `## 항목`은 반드시 유지하며 본문은 정확히 `내용`으로 둔다. `## 요약`이 있으면 항목 바로 뒤에 둔다.
- `###`와 `####`는 고유명이 있거나 독립 조회 가치·별도 생태권·이동 규율·위험을 가진 내부 지형에만 사용한다. 문단 수를 맞추거나 긴 내용을 정확히 두 문단씩 나누기 위해 제목을 추가하지 않는다.
- 각 실질 설정 섹션의 최소 두 문단은 하한선이다. 같은 주제가 이어지면 세 문단 이상을 자연스럽게 작성하며, 최대 두 문단으로 제한하지 않는다.

### 설화 문서

- `type: 설화`는 세계 안에서 실제로 유통되는 전승·민담·소문·이본을 기록할 때 사용한다.
- 설화 문서는 확인된 관측 사실과 전승의 해석을 분리하고, 서로 다른 판본을 하나의 사실로 합치지 않는다.
- 특정 존재의 확정 설정은 해당 정본 문서에 두고, 기원·목적·과거처럼 검증되지 않은 이야기는 별도 설화 문서에서 출처와 판본별로 기록한다.

## 정치체제·생존 정책·갈등 관계

정치체제는 누가 어떤 권한과 절차로 결정을 내리는지를 설명한다. 생존 정책은 그 권력이 안개·잔향·오염·던전성 변동·재난 앞에서 보호 대상, 자원 배분, 정보 공개, 난민 수용, 봉쇄와 허용 가능한 희생을 어떻게 정하는지를 설명한다. 두 항목을 혼합하지 않으며, 국가 정책을 가리킬 때 `생존 교리`, `생존 노선` 등의 표현을 사용하지 않고 `생존 정책`으로 통일한다.

정치 관련 설정을 작성하거나 수정할 때에는 다음 순서로 근거를 확인한다.

1. 관련 인덱스에서 대상 국가·도시국가·관계 문서를 찾는다.
2. 개별 국가·부족국가·도시국가·항구 설정 문서와 관련 대륙 문서를 읽어 확정 사실을 확인한다.
3. 관련 `세력 관계` 문서에서 기존 관계 상태와 갈등 원인을 확인한다.
4. `라이브러리/정치체제 라이브러리.md`의 용어·분류·조립 규칙을 적용한다.

정치체제 라이브러리의 프리셋은 국호나 문화 모티브만으로 선택하지 않는다. 명목상 최고 권력자, 실질 권력 집단, 권력 집중도, 행정 방식, 승계 방식, 중앙과 지역 또는 구성원의 권력 배분, 통치 정당성을 함께 확인한다. 개별 정본에 없는 통치 기구를 라이브러리만 근거로 확정하지 않는다.

국가의 정치체제나 생존 정책을 변경하면 해당 국가 문서만 수정하지 않는다. 관련 세력 관계 문서, 정치 체제 인덱스, 통합 인덱스를 함께 점검하며, 정치체제의 정의·명칭·적용 사례가 달라졌을 때에는 정치체제 라이브러리도 갱신한다. 반대로 라이브러리와 인덱스만 수정하여 개별 정본보다 먼저 설정을 확정해서는 안 된다.

갈등 관계는 `우호`, `견제`, `대립`, `전쟁`이라는 상태만 기록하지 않는다. 상호 의존 자원, 핵심 쟁점, 각자의 생존 정책, 분쟁 거점, 협력 조건, 금지선, 관계 악화의 촉발 조건이 개별 국가 문서와 관계 문서에서 서로 일치하도록 작성한다.

항구와 도시국가를 정비할 때에는 설립 주체, 현재 주권자, 후원·보호 세력, 주권 상태, 통치체제, 생존 기능을 분리한다. 특정 국가의 지원으로 건설되었다는 사실만으로 그 국가의 영토나 `령`으로 확정하지 않는다. 독립 자유시, 보호 도시국가, 헌장 자치도시, 직할령, 공동통치령, 중립 도시, 연맹령 등의 지위는 개별 설정과 대륙 정치 관계를 근거로 판단한다.

어둠과 앙그라는 명확히 구분한다. 에레보스가 다루는 어둠의 신성은 앙그라의 안개·잔향·오염이 아니며, 룬다르 신성 제국은 어둠 자체를 정화하거나 통제하려 하지 않는다. 룬다르와 에레보스 사이의 정치적 마찰은 필요한 경우 앙그라의 안개에 대한 정보 공개, 격리, 검역, 정화 관할과 대응 절차의 차이로 다룬다.

## 용종 명명 규칙

용종을 새로 작성하거나 이름을 변경할 때에는 [[용종]]의 분류 정의, 대상 생태권과 용성 정본, `라이브러리/용종 명명 라이브러리.md`를 함께 읽는다. 정식 명칭은 기본적으로 `별칭 + 고유명` 구조를 사용하며, 별칭은 핵심 속성·기관·행동·환경과 생물형 종결어를 조합한다. 분류명만으로 별칭을 대신하거나 기존 외부 작품의 명칭을 변형해 사용하지 않는다.

종결어는 대상의 실제 생물 기반과 실루엣을 우선하여 정한다. 비룡종·수룡종·해룡종·아룡종·어룡종·사룡종은 `~룡`을 기본으로 하며, 조룡종은 조류형 `~조`와 지상 군집형 `~룡`을 구분한다. 갑각종의 게형은 `~해(蟹)`, 갑충종은 `~충` 또는 구체 곤충형, 협각종의 거미형은 `~지주`, 양서종의 개구리형은 `~와`, 두족종의 문어형은 `~소`를 우선한다. 세부 예외와 식생종·익룡종·초식종의 종결어는 용종 명명 라이브러리의 분류표를 따른다.

고룡종과 재해룡종은 별도의 혈통 분류가 아니므로 위상이나 변질 상태만으로 기존 종명을 바꾸지 않는다. 아종·지역 변종·성장 단계·성별·계절색을 구분하고, 안정적인 생태와 기관 차이가 확인될 때에만 새 별칭이나 고유명을 부여한다. 사용자가 확정하기 전의 이름 후보를 정본 문서에 반영하지 않으며, 확정 전에는 기존 설정 전체에서 동일·유사 명칭을 검색한다.

## 라이브러리 갱신 규칙

라이브러리는 개별 정본에서 확인되거나 사용자가 명시적으로 확정한 구조를 일반화하여 작성한다. 실제 적용 사례가 없는 후보 체제는 확정 프리셋과 구분하며, 후보를 라이브러리에 추가했다는 이유만으로 개별 국가에 자동 적용하지 않는다.

정치체제 항목에는 최소한 뜻, 의사결정 구조, 주요 권력 집단, 강점, 구조적 취약점, 설정할 때 확인할 질문, 룩스테라 적용 사례를 포함한다. 생존 정책은 정치체제 프리셋 안에 고정하지 않고 각 국가·도시국가 문서에서 별도로 정한다.

## 설정 정비와 스토리 설계

- `설정 정비`: `title`, `uuid`, `docType: maintenance`, `thumbnail: ''`, `status`, `created_at`, `updated_at`, `completed_at`을 사용한다. `status`는 `대기`, `진행 중`, `검증 중`, `완료`, `보류`, `폐기` 가운데 하나이며, `completed_at`은 완료 상태에서만 채운다. 기존 `progress` 필드는 사용하지 않는다.
- `스토리 설계`: `title`, `type`, `progress`, `written_on`, `updated_at`을 사용한다. `type`은 `스토리` 또는 `구상`, `progress`는 `진행중`, `진행완료`, `설계중`, `준비중`, `작성완료` 중 하나다.

## 설정 정비 운영 절차

1. `설정 정비 현황.md`에서 중복 작업과 선행·차단 요소를 확인한다.
2. 같은 범위의 미완료 작업이 있으면 새 문서를 만들지 않고 기존 문서에 발견 사항, 적용 내역, 검증 결과를 갱신한다.
3. 독립적으로 처리할 수 있는 미해결 사항은 별도 정비 문서로 분리하고 양쪽 문서와 현황에서 연결한다.
4. 완료된 정비 문서는 삭제하지 않는다. 현재 설정 사실은 항상 최신 정본에서 다시 확인한다.

## 신격 문서

`title`, `uuid`, `docType: deity`, `thumbnail: ''`, `pantheon`, `cheongyeon_pantheon`, `status`, `rank`, `alignment`, `domain`, `portfolio`, `created_at`, `updated_at`을 사용한다. 본문은 `## 개요` 이하 내용을 유지한다.

- `status`: `시작 전`, `진행 중`, `완료`
- `rank`: 문맥에 맞게 `반신격`, `소신격`, `중신격`, `대신격`, `주신격`, `초신격` 등을 사용한다.
- `alignment`: 문맥에 맞게 `선신`, `회색신`, `악신` 등을 사용한다.
- `domain`, `portfolio`: 문자열 배열로 기록한다.

## 본문 섹션 골격

문서의 첫 `##` 섹션은 `개요`로 둔다. 이후 실제 내용 섹션은 선택이며, 모든 문서에 `## 항목`을 둔다. `항목`의 본문은 공백을 제외하고 정확히 `내용`으로 고정한다. 실제 요약이 있을 때만 `## 요약`을 `항목` 아래에 두므로, `항목`은 항상 마지막 섹션이거나 `요약` 바로 앞의 마지막에서 두 번째 섹션이다.

## 세력 관계와 링크

세력 관계 문서는 `title`, `relation`, `a_setting`, `a_god`, `b_setting`, `b_god`, `issue`, `session_signs`, `visibility`을 사용한다.

- `relation`: `우호`, `견제`, `대립`, `전쟁`
- `visibility`: `공개`, `부분 공개`, `비공개`
- 연결 항목은 내부 위키 링크 `[[문서명]]`으로 기록한다.

내부 링크의 대상은 현재 설정 폴더에 존재하는 실제 파일명과 일치시킨다. 대상이 없거나 연결이 모호하면 수동 검토 목록으로 분리한다.
