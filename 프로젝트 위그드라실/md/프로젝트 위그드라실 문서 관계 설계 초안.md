# 프로젝트 위그드라실 문서 관계 설계 초안

> 상태: 검토용 초안. 카테고리 이관 기준을 전제로 하며, 실제 테이블·API·이관은 브레인스토밍 후 확정한다.

## 1. 목적과 범위

이번 이관 대상인 설정·신격·비밀 설정은 모두 단일 `documents` 모델에 들어간다. 관계는 단순한 문서 링크가 아니라, 두 문서 사이에 성립하는 설정 사실을 저장한다.

관계는 다음과 같은 질문에 답할 수 있어야 한다.

- 어떤 인물이 어떤 단체에 소속되었는가.
- 어떤 인물이 어느 국가 또는 지역 출신인가.
- 어떤 도시·지형·거점이 어느 국가 또는 상위 지역 안에 있는가.
- 어떤 아이템을 누가 소유·보관·사용·제작하는가.
- 어떤 지역에서 어떤 설화가 전승되는가.
- 어떤 국가·단체·신격·인물이 동맹, 적대, 견제, 의존 관계인가.

관계는 문서의 카테고리를 대체하지 않는다. 문서 하나는 하나의 카테고리를 가지며, 관계는 그 문서가 다른 문서와 맺는 사실을 표현한다.

## 2. 핵심 모델

관계 한 건은 아래의 문장으로 읽힌다.

```text
주체 문서 ── 관계 유형 ──> 대상 문서
```

예시:

```text
인물 A ── 소속 ──> 단체 B
도시 C ── 포함됨 ──> 국가 D
아이템 E ── 소유됨 ──> 인물 A
지역 F ── 전승함 ──> 설화 G
```

관계는 한 번만 저장하고, 조회 화면에서 반대 방향의 문장도 표시한다. 예를 들어 `인물 A → 소속 → 단체 B`가 있으면 단체 B에서는 `소속 인물: 인물 A`로 보인다. 같은 사실을 양방향으로 중복 저장하지 않는다.

## 3. 관계 유형이 가져야 할 공통 정보

후속 테이블 설계에서는 관계 유형과 실제 관계 레코드를 분리한다.

| 구분 | 역할 |
| --- | --- |
| 관계 유형 | 코드, 표시명, 역관계 표시명, 방향성, 대칭 여부, 설명, 허용 카테고리 조합 |
| 관계 레코드 | 주체 문서, 대상 문서, 관계 유형, 설명, 공개 범위, 유효 기간, 정렬 순서, 보조 속성 |

관계 레코드에는 최소한 다음 의미를 보존한다.

- `설명`: 관계의 구체적 내용과 예외
- `공개 범위`: 공개·부분 공개·비공개. 비밀 설정을 대상으로 한 관계도 같은 기준으로 제어한다.
- `유효 기간`: 현재, 과거, 예정 또는 시작·종료 시점
- `보조 속성`: 역할, 직책, 지위, 소유 상태, 조약명, 계승 순서처럼 관계 유형별로 달라지는 값
- `근거`: 원전 문서, 본문 섹션, 이관 메모. 설정 충돌을 추적할 수 있어야 한다.

## 4. 관계 유형 초안

### 4.1 공간·포함 관계

| 주체 → 대상 | 관계 | 역관계 | 대표 사용처 |
| --- | --- | --- | --- |
| 도시·지형·거점 → 국가·지역 | 위치함 | 포함함 | 도시가 국가 안에 있음 |
| 국가·도시·지형 → 대륙·지형 | 속함 | 포함함 | 국가·지역의 공간 귀속 |
| 단체 → 도시·국가·지형 | 본거지를 둠 | 본거지임 | 단체의 거점·본부 |
| 단체·국가 → 지역 | 관할함 | 관할됨 | 행정권, 통치권, 보호구역 |
| 지역·도시 → 지역·도시 | 연결됨 | 연결됨 | 항로, 관문, 이동 경로 |

`포함함`은 공간적·행정적 귀속을 뜻한다. 상호 대칭 관계가 아니며, 국가가 도시를 포함한다고 해서 도시가 국가를 포함하는 것은 아니다.

### 4.2 정체성·소속·기원 관계

| 주체 → 대상 | 관계 | 역관계 | 보조 속성 예시 |
| --- | --- | --- | --- |
| 인물 → 단체 | 소속 | 소속 인물 | 역할, 직책, 계급, 재임 기간 |
| 인물 → 국가·도시·지역 | 출신 | 출신 인물 | 출생, 성장, 귀화, 망명 |
| 인물 → 인물 | 혈연 | 혈연 | 관계명, 친족 등급 |
| 인물 → 인물·단체 | 사사·양성 | 제자·피양성자 | 관계 성격, 기간 |
| 단체 → 단체·국가 | 하위 조직·종속 | 상위 조직·종주 | 권한 범위, 자치 여부 |
| 종족·용종 → 지역 | 기원함 | 기원지임 | 기원 시기, 이주 여부 |

`소속`과 `출신`은 다르다. 인물이 한 국가 출신이면서 다른 국가의 단체에 소속될 수 있으므로, 하나의 컬럼이나 단일 참조로 합치지 않는다.

### 4.3 소유·제작·운용 관계

| 주체 → 대상 | 관계 | 역관계 | 보조 속성 예시 |
| --- | --- | --- | --- |
| 인물·단체·국가 → 아이템 | 소유 | 소유자 | 법적 소유, 공동 소유, 상속 |
| 인물·단체·국가 → 아이템 | 보관·관리 | 보관처·관리자 | 보관 상태, 접근 권한 |
| 인물·단체·국가 → 아이템 | 사용 | 사용자 | 운용 자격, 사용 기간 |
| 인물·단체 → 아이템 | 제작 | 제작자 | 제작 시기, 공방, 원형 |
| 아이템 → 인물·단체·국가 | 헌정·수여됨 | 수여함 | 수여 사유, 의식, 날짜 |
| 아이템 → 사건 | 관련됨 | 관련 유물 | 사용, 발견, 소실 |

소유자와 사용자는 분리한다. 왕국이 유물을 소유하고 특정 인물이 운용하는 상황을 동시에 기록할 수 있어야 한다.

### 4.4 정치·사회·신앙 관계

| 주체 → 대상 | 관계 | 역관계 | 비고 |
| --- | --- | --- | --- |
| 국가·단체 → 국가·단체 | 동맹 | 동맹 | 대칭 관계 |
| 국가·단체 → 국가·단체 | 적대 | 적대 | 대칭 관계 |
| 국가·단체 → 국가·단체 | 견제 | 견제 | 대칭 관계, 현재 관계 문서의 주요 사례 |
| 국가·단체 → 국가·단체 | 협력 | 협력 | 대칭 관계 |
| 국가·단체 → 국가·단체 | 경쟁 | 경쟁 | 대칭 관계 |
| 국가·단체 → 국가·단체 | 의존 | 의존 대상 | 자원·보호·정보 등 의존 사유 기록 |
| 국가·단체 → 국가·단체 | 교역 | 교역 | 대칭 관계, 품목·경로는 보조 속성 |
| 인물·단체·국가 → 신격 | 신앙·숭배 | 신앙 대상 | 교단, 신앙 형태, 공개 범위 |
| 신격 → 인물·단체·국가 | 가호·후원 | 가호 대상 | 조건, 대가, 철회 가능성 |

`동맹·적대·견제·협력·경쟁·교역`은 대칭 관계다. `의존`과 `가호·후원`은 어느 쪽이 의존하거나 후원하는지를 보존해야 하므로 방향 관계다.

### 4.5 사건·인과 관계

| 주체 → 대상 | 관계 | 역관계 | 보조 속성 예시 |
| --- | --- | --- | --- |
| 인물·단체·국가 → 사건 | 참여 | 참여자 | 역할, 진영, 결과 |
| 인물·단체·국가 → 사건 | 주도 | 주도자 | 의도, 책임, 지휘권 |
| 사건 → 사건·상태 | 촉발함 | 촉발됨 | 인과 설명, 직접·간접 여부 |
| 사건 → 국가·도시·지형·단체 | 영향 | 영향받음 | 변화 내용, 지속 기간 |
| 사건 → 인물 | 사망·실종·변질시킴 | 관련 사건 | 결과 상태, 확정 여부 |
| 사건 → 아이템·문서 | 발견·소실·생성 | 관련 사건 | 발견자, 보관처, 현재 상태 |

사건은 참여자와 원인을 구분한다. 같은 단체가 사건에 참여했더라도 주도자가 아닐 수 있으며, 사건이 다른 사건을 촉발할 수도 있다.

### 4.6 생태·설화·개념 관계

| 주체 → 대상 | 관계 | 역관계 | 대표 사용처 |
| --- | --- | --- | --- |
| 종족·용종 → 지역 | 서식·분포 | 서식지·분포지 | 종족과 용종의 생활권 |
| 종족·용종 → 종족·용종 | 포식·경쟁·공생 | 피식·경쟁·공생 | 생태 관계 |
| 지역·국가·도시 → 설화 | 전승 | 전승지 | 지역에서 전해지는 설화 |
| 설화 → 인물·사건·지역·아이템 | 다룸 | 소재임 | 설화가 다루는 대상 |
| 설화 → 설화 | 이본 | 원전·이본 | 판본·변형 관계 |
| 개념 → 문서 | 규정·설명 | 적용·설명 대상 | 신위, 용성, 클래스 체계 등 |

`이본`은 설화의 카테고리가 아니라 관계 또는 태그다. 특정 설화가 다른 설화의 이본일 때는 관계를 사용하고, 단순히 판본이 존재한다는 상태만 표시할 때는 태그를 사용한다.

## 5. 입력과 조회 규칙 초안

1. 관계 입력 시 주체·관계·대상을 모두 선택한다. 자유 텍스트 링크만으로 관계를 생성하지 않는다.
2. 관계 유형별로 허용하는 카테고리 조합을 둘 수 있으나, 초기에는 검증 경고로만 사용한다. 새 월드의 고유 관계를 막지 않는다.
3. 대칭 관계는 하나의 레코드만 만들고 양쪽 문서에서 동일하게 조회한다.
4. 방향 관계는 역관계 표시명을 함께 정의한다. 예: `소속`의 역표시는 `소속 인물`, `소유`의 역표시는 `소유자`다.
5. 동일한 주체·관계·대상 조합이라도 기간·역할·상태가 다르면 별도 관계로 기록할 수 있다.
6. 공개 범위가 낮은 관계는 대상 문서가 공개여도 관계 자체를 숨길 수 있어야 한다.
7. 본문 링크는 참고 링크로 남길 수 있지만, 검색·필터·관계도·역참조의 기준은 구조화된 관계 레코드다.

## 6. 기존 세력 관계 문서의 이관 방향

기존 `세력 관계` 문서는 이번 문서 이관 대상에는 포함하지 않는다. 다만 향후 관계 데이터를 만들 때 아래 정보를 우선 추출한다.

| 기존 항목 | 관계 초안에서의 처리 |
| --- | --- |
| `a_setting`, `a_god`, `b_setting`, `b_god` | 관계의 주체·대상 문서 |
| `relation` | 관계 유형 |
| `visibility` | 관계 공개 범위 |
| `issue` | 관계 설명 또는 핵심 쟁점 |
| `session_signs` | 관계의 현장 징후 또는 세션용 보조 정보 |

한 관계 문서에 동맹과 견제처럼 여러 성격이 함께 있으면, 하나의 넓은 관계로 뭉치지 않고 의미별 관계 레코드로 나눈다. 세부 맥락은 설명과 보조 속성에 보존한다.

## 7. 검토가 필요한 항목

- 관계 유형을 모두 공통 목록으로 둘지, 월드별 추가 유형을 허용할지
- `출신`, `출생`, `성장`, `귀화`, `망명`을 하나의 관계와 상태값으로 둘지, 각각 독립 관계로 둘지
- 국가의 공간 포함과 행정 관할을 언제 분리할지
- 아이템의 소유·보관·사용·제작 관계에 필요한 공통 보조 속성 범위
- 관계의 유효 시점을 연도·시대·자유 서술 중 무엇으로 저장할지
- 관계 충돌 또는 상충하는 전승을 어떤 상태값으로 보존할지
