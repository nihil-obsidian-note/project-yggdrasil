# 카테고리 및 관계 설계 인계서

> 목적: 다른 GPT 대화에서 프로젝트 위그드라실의 문서 이관 설계를 중단 없이 이어가기 위한 현재 상태 요약이다.
>
> 상태: 범용 카테고리 기준과 범용 관계 유형 2.1~2.15의 COMMON 936개 관계·대상 역할 2,813개를 확정했다. 신규 관계 파트는 2.15에서 종료하며, 전체 종료 감사와 v1 동결 후 실제 DB 이관 구조 설계로 전환한다.

## 1. 이번 정리를 시작한 이유

기존 Markdown 문서는 `type`, `subtype`, 문서 폴더, `주요`, `일반` 값이 서로 다른 성격의 정보를 함께 담고 있었다. 이를 그대로 데이터베이스에 옮기면 문서 종류, 설정 중요도, 세계관 분류, 문서 용도가 뒤섞인다.

따라서 먼저 문서가 무엇에 관한 문서인지를 일관된 카테고리로 다시 정리했다. 그 다음에는 문서 링크만으로는 인물의 소속, 도시의 국가 귀속, 아이템의 소유자, 지역에 전해지는 설화처럼 의미 있는 사실을 검색·역추적할 수 없으므로, 방향과 의미를 가진 관계를 새로 설계한다.

## 2. 확정된 문서 모델 방향

- 이관 대상은 `설정`, `신격`, `비밀 설정`이다.
- 세 문서군은 모두 하나의 `documents` 모델에 들어간다.
- 비밀 설정은 문서 유형이 아니라 공개 범위 컬럼으로 제어한다.
- `importance`는 문서 관리·열람 중요도 컬럼이다.
- 문서 하나는 카테고리 하나만 선택한다. 복수 성격, 속성, 상태, 위계는 태그와 관계로 표현한다.
- 범용 카테고리는 개념·신격·국가·도시·단체·종족·인물·아이템·사건·설화·지형의 11개다.
- 룩스테라에는 `용종`, 엘드로스에는 `클래스`가 세계별 확장 카테고리로 추가된다.
- 모든 범용 관계의 기본 대상 카테고리 매핑은 범용 11개만 사용하며, 세계별 확장 카테고리는 자동 포함하지 않는다.
- `스토리 설계`, `설정 정비`, 템플릿, 지침, 라이브러리, 인덱스는 이번 이관 대상이 아니다.
- 관계 인스턴스는 2~4개의 문서 참여 대상을 가지며, 각 대상은 관계 안에서 의미 역할을 가진다.

## 4. 2.9 확정 처리

2.9는 총 44개 relation type으로 최종 확정했다.

기존 relation type을 재사용하는 후보는 다음과 같다.

- `활동함` → 2.1
- `기원함`, `이주함`, `정착함` → 2.2
- `변이 원인임(자연)`, `오염시킴(질병)` → 2.5.1

후보 간 통합은 다음과 같다.

- `섭식함` → `먹이로 삼음`
- `숙주로 삼음` → `기생함 ↔ 숙주임`

정밀 검토 중 다음 관계를 신규 추가했다.

- `수분을 매개함`
- `종자를 확산시킴`
- `서식지를 제공함`

`침입종임`의 직접 대상과 역방향 표시명은 다른 토착·유입 관계와 같은 기준으로 `침입 지역`, `침입 지역임`으로 확정했다. 생태계 교란 여부는 2.13의 영향 관계에서 별도로 표현한다.

다음 후보는 2.13 개념·법칙·영향으로 넘긴다.

- `개체수를 감소시킴`
- `개체수를 증가시킴`
- `멸종시킴`
- `생태계를 교란함`
- `생태계를 안정시킴`

## 5.1 2.11 및 세계별 확장 매핑

2.11 신앙·권능·초월 관계 34개를 확정했다. `파문함 ↔ 파문당함`은 전역 번호 55를 유지한 채 2.2에서 2.11-4로 재분류했으며, 신규 COMMON 관계는 33개다.

| 범용 범위 | 활성 관계 | 대상 역할 |
| --- | ---: | ---: |
| 2.1~2.10 | 752 | 2,139 |
| 2.11 | 34 | 125 |
| **누적** | **786** | **2,264** |

세계별 확장은 범용 정본과 분리한다.

- 룩스테라 용종: COMMON 674개 관계, 1,240개 역할 허용
- 엘드로스 클래스: 기존 COMMON 74개 관계, 80개 역할 허용
- 엘드로스 클래스 전용: SERIES 7개 관계, 25개 대상 역할
- 적용 규칙: 범용 `COMMON` 매핑과 시리즈 `SERIES` 매핑의 합집합
- 클래스 전용 관계: 보유·각성·부여·박탈·상실·전직·사용 자격

2.11과 2.12의 이관 미처리 관계는 없다. 다음 범용 검토 파트는 2.13 개념·법칙·영향이다.

## 6. 다음 대화에서 이어갈 권장 순서

관계 유형 검토를 이어갈 때에는 아래 순서를 고정한다.

1. `프로젝트 위그드라실 문서 관계 설계 초안.md`에서 다음 검토 파트의 원래 범위와 비어 있는 의미 영역을 먼저 분석한다.
2. 이미 확정된 2.1~2.11 관계 문서와 `범용 관계 유형 검토·이관 추적 문서.md`를 대조하여 중복, 재사용 관계, 이관 대기 후보를 확인한다.
3. 그 결과를 토대로 2.13 개념·법칙·영향의 **검토 대상 전체**를 먼저 리스트업한다. 번호만 보고 역할을 추정하지 않는다.
4. 세부 파트 전체를 한 번에 검토한다. 검토 과정에서 신규 관계를 추가하거나 기존 후보를 통합·재사용·후속 파트 이관·제외할 수 있다.
5. 모든 후보에서 일반 관계, 괄호형 독립 관계, 보조 속성 가운데 적절한 표현 방식을 함께 판정한다.
6. 사용자 확정 후에만 해당 파트 확정본과 추적·정비 문서를 갱신한다.
7. 범용 관계 유형 전체가 확정된 뒤 관계 유형·관계 레코드의 DB 구조와 UI 표시 규칙을 최종 설계한다.

검토 대상 표는 `정방향 | 역방향 | 방향 | 대상 수 | 대상 역할·허용 카테고리 | SERIES 확장 | 템플릿 | 판단` 구조를 사용한다.
