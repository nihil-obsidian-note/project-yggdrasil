# 범용·세계별 관계 대상 카테고리 매핑 적용 규칙

> 상태: 확정  
> 적용 범위: 범용 관계 유형 2.1~2.11과 세계별 확장 카테고리·전용 관계

## 1. 정본 구성

| 계층 | 정본 | 역할 |
| --- | --- | --- |
| 범용 2.1~2.10 | `2.1~2.10 관계 대상 카테고리 매핑.md` | 모든 세계에 공통 적용되는 11개 카테고리 |
| 범용 2.11 | `2.11 관계 대상 카테고리 매핑.md` | 2.11 관계 34개의 범용 역할 매핑 |
| 룩스테라 확장 | `룩스테라 용종 관계 대상 확장 매핑.md` | 룩스테라에서만 용종을 추가 허용 |
| 엘드로스 확장 | `엘드로스 클래스 관계 대상 확장 매핑.md` | 기존 범용 역할에 클래스를 추가 허용하고 전용 관계를 연결 |
| 엘드로스 전용 관계 | `엘드로스 클래스 전용 관계 추가 확정본.md` | 엘드로스에서만 활성화되는 SERIES relation type 7개 |

각 정본은 서로 합치지 않는다. 범용 정본은 세계별 카테고리를 포함하지 않으며, 세계별 확장 정본은 추가 허용 역할과 전용 relation type의 연결만 기록한다.

## 2. 적용 순서

1. 선택한 relation type의 대상 역할을 불러온다.
2. 관계 파트에 따라 2.1~2.10 또는 2.11 범용 정본에서 해당 역할의 범용 허용 카테고리를 불러온다.
3. 현재 시리즈가 룩스테라라면 용종 확장 매핑을 합친다.
4. 현재 시리즈가 엘드로스라면 클래스 확장 매핑을 합치고, 엘드로스 전용 relation type 7개를 선택 목록에 추가한다.
5. 합쳐진 카테고리만 문서 선택기에 노출한다.
6. 저장 시 동일 허용 집합으로 다시 검증한다.
7. 다른 시리즈의 확장 카테고리는 조회·저장 후보에 포함하지 않는다.

## 3. DB 연결 구조

### relation_target_roles

관계 유형 안의 의미 역할을 저장한다.

| 필드 | 의미 |
| --- | --- |
| id | 대상 역할 식별자 |
| relationTypeId | 관계 유형 |
| roleKey | 역할 키 |
| roleName | 표시명 |
| minCount | 최소 입력 수 |
| maxCount | 최대 입력 수 |
| sortOrder | 역할 순서 |

### relation_role_category_mappings

대상 역할이 허용하는 카테고리와 적용 범위를 저장한다.

| 필드 | 의미 |
| --- | --- |
| id | 매핑 식별자 |
| relationTargetRoleId | 대상 역할 |
| categoryId | 허용 카테고리 |
| scopeType | `COMMON` 또는 `SERIES` |
| seriesCode | `SERIES`일 때 `LUXTERRA` 또는 `ELDROS` |
| useYn | 사용 여부 |
| createDate | 생성 일시 |
| updateDate | 수정 일시 |
| deleteDate | 삭제 일시 |

고유 제약은 `(relationTargetRoleId, categoryId, scopeType, seriesCode)`로 둔다. `scopeType=COMMON`일 때 `seriesCode`는 비워 두고, `scopeType=SERIES`일 때만 필수로 검증한다.

## 4. 조회 규칙

허용 카테고리는 다음 합집합으로 계산한다.

[
Allowed(role, series) = Common(role) \cup SeriesExtension(role, series)
]

현재 구조에는 세계별 금지 덮어쓰기가 없다. 범용 허용을 특정 세계에서 제거해야 하는 요구가 생기기 전까지 `DENY` 규칙이나 우선순위 열을 추가하지 않는다.

## 5. 무결성 규칙

- 범용 매핑은 범용 11개 카테고리만 가질 수 있다.
- 룩스테라 확장 매핑의 카테고리는 `용종`만 허용한다.
- 기존 범용 역할에 추가하는 엘드로스 확장 매핑의 카테고리는 `클래스`만 허용한다.
- 엘드로스 전용 relation type은 자체 역할 정의에 범용 카테고리와 `클래스`를 함께 명시할 수 있다.
- 확장 매핑은 범용 매핑의 복제 행을 만들지 않는다.
- 대상 역할이 삭제되거나 비활성화되면 연결 매핑도 조회에서 제외한다.
- 새 시리즈 전용 카테고리는 기존 `전체 11개` 역할에 자동 추가하지 않는다.
- 관계 입력 UI와 서버 저장 검증은 같은 허용 집합 계산 함수를 사용한다.

## 6. UI 표시

- 룩스테라: 범용 허용 카테고리 + 허용된 역할의 용종
- 엘드로스: 범용 허용 카테고리 + 허용된 역할의 클래스
- 그 외 시리즈: 범용 허용 카테고리만 표시
- 클래스는 인물 검색 결과에 섞지 않고 클래스 탭 또는 카테고리 필터로 분리한다.
- 용종은 인물과 같은 역할에 허용되더라도 용종 카테고리 탭으로 분리한다.

## 7. 엘드로스 전용 관계 확정

엘드로스 클래스 매핑 검토에서 보존했던 후보를 확장해 전용 relation type 7개를 최종 확정했다.

| 범위 | relation type | 수량 |
| --- | --- | ---: |
| `COMMON` | 2.1~2.11 범용 관계 | 786 |
| `SERIES:ELDROS` | 클래스 전용 관계 | 7 |

전용 관계는 `COMMON` 수량에 포함하지 않는다. 기존 범용 관계 호환 슬롯은 과거 데이터 조회를 위해 유지하되, 신규 입력에서는 전용 관계를 우선한다.


## 2.12 적용 갱신

- COMMON은 `2.12 관계 대상 카테고리 매핑.md`의 전역 ID 787~841을 추가 적용한다.
- 룩스테라 용종은 해당 COMMON 역할과 `룩스테라 용종 관계 대상 확장 매핑.md`의 2.12 절을 합집합으로 적용한다.
- 엘드로스 클래스는 2.12에 추가 허용 역할이 없다.
- COMMON 누적은 841개 관계·2479개 역할이다.


## 2.13 적용 갱신

- COMMON은 `2.13 관계 대상 카테고리 매핑.md`의 전역 ID 842~886을 추가 적용한다.
- 룩스테라 용종은 해당 COMMON 역할과 `룩스테라 용종 관계 대상 확장 매핑.md`의 2.13 절을 합집합으로 적용한다.
- 엘드로스 클래스는 해당 COMMON 역할과 `엘드로스 클래스 관계 대상 확장 매핑.md`의 2.13 절을 합집합으로 적용한다.
- 기존 ID 836은 COMMON 관계를 재사용하되 엘드로스 클래스 역할 확장만 추가한다.
- COMMON 누적은 886개 관계·2634개 역할이다.


## 2.14·2.15 적용 갱신

- COMMON 전역 ID 887~936과 대상 역할 179개를 추가 적용한다.
- SERIES 카테고리는 각 확정본에 명시된 역할에만 합집합으로 적용한다.
- 2.15를 마지막 신규 파트로 하고 종료 감사 후 관계 유형 v1을 동결한다.
- 누적 COMMON은 936개 관계·2813개 역할이다.
