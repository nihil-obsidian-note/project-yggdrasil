# 템플릿 구조 점검 수칙

## 문서 역할

이 문서는 `프로젝트 위그드라실` 설정 루트를 작업 공간으로 직접 열었을 때, 외부 프롬프트에 의존하지 않고 설정 문서의 템플릿 구조를 점검할 수 있도록 만든 독립 실행 수칙이다.

설정 문서를 작성·수정·개편·병합·분리하거나 구조 일치 여부를 점검할 때에는 프로젝트 루트 `AGENTS.md`, `문서 작성 및 수정 지침.md`, 대상 시리즈 `AGENTS.md`, 대상 템플릿과 함께 이 파일을 읽는다.

`TRPG 데이터/프롬프트/8. 설정 관련 요청 프롬프트/3. 설정 문서 템플릿 구조 점검 수칙.md`는 프롬프트 실행용 대응 문서다. 한쪽 수칙을 개정하면 다른 쪽도 같은 작업에서 갱신하여 핵심 판정 규칙을 동일하게 유지한다.

## 적용 목적

설정 문서의 구조 점검은 대상 문서가 같은 시리즈의 최신 템플릿과 동일한 문서군으로 작성되었는지 확인하는 절차다. 점검의 대상은 프론트매터의 분류 체계, 필수 상위 섹션의 이름과 순서, 제목 단계, 특수 섹션의 위치, 내용이 배치된 범주다. 문서의 분량이나 문체가 우수하더라도 적용 템플릿이 잘못되었거나 상위 구조가 다른 문서군의 형태로 변형되었다면 구조 점검을 통과한 것으로 보지 않는다.

템플릿 일치는 문서의 모든 문장과 하위 제목을 템플릿에 그대로 복제하는 것을 뜻하지 않는다. 필수 `##` 구조와 프론트매터 기준은 지키되, 문서 고유의 내부 지형·제도·파벌·사건처럼 독립적으로 조회할 가치가 있는 내용은 올바른 상위 섹션 아래에서 `###` 또는 그 이하 제목으로 확장할 수 있다. 두 문단은 섹션의 최소 기준일 뿐 최대치가 아니며, 문단 수를 맞추기 위해 제목을 늘리거나 정확히 두 문단마다 새 섹션을 만드는 행위는 금지한다.

## 적용 조건

아래 요청에서는 이 수칙을 반드시 적용한다.

- 특정 문서가 현재 템플릿과 같은 구조인지 확인하는 요청
- 템플릿 준수, 양식 일치, 섹션 순서, 상위 제목, 프론트매터 구조 점검
- 설정 문서의 신규 작성, 보강, 개편, 재작성
- 문서 병합·분리 후 구조 재배치
- `type` 또는 `subtype` 변경이 포함된 작업
- 새 템플릿 작성 또는 기존 템플릿 개정
- 여러 설정 문서의 템플릿 준수 여부 일괄 점검
- 템플릿이 존재하는 문서의 수정본 또는 ZIP 산출물 작성

단순 조회나 사실 확인만 수행하고 문서 구조를 변경하지 않는 경우에는 전체 구조 감사를 생략할 수 있다. 그러나 사용자가 구조 일치 여부를 직접 묻거나 대상 문서를 수정한다면 반드시 적용한다.

## 기준 자료와 우선순위

구조 판정은 대상 문서와 같은 설정 루트 안의 최신 자료를 사용한다. 로컬에 남아 있는 이전 사본이나 다른 시리즈의 유사 문서를 편의상 기준으로 삼지 않는다.

자료는 다음 순서로 확인한다.

1. 프로젝트 설정 루트의 `AGENTS.md`
2. 프로젝트 설정 루트의 `문서 작성 및 수정 지침.md`
3. 이 `템플릿 구조 점검 수칙`
4. 대상 시리즈 또는 공통 설정 폴더의 `AGENTS.md`
5. 대상 시리즈의 `템플릿` 폴더
6. 점검 대상 문서
7. 같은 유형·하위 유형의 정상 적용 사례
8. 제목 변경이나 섹션 이동의 영향을 받는 역참조 문서와 인덱스

템플릿은 형식과 메타데이터의 기준이며, 개별 설정 사실의 근거는 아니다. 템플릿에 없는 설정을 삭제하거나, 템플릿의 예시 문장을 세계관 사실로 복사해서는 안 된다. 반대로 개별 문서에 반복적으로 나타나는 새로운 상위 범주가 기존 템플릿에 들어갈 자리가 없다면 문서를 임의로 변형하기보다 `템플릿 보강 필요`로 판정한다.

## 적용 템플릿 판정

적용 템플릿은 파일명만 보고 고르지 않는다. 프론트매터, 저장 폴더, 시리즈 지침, 문서의 실제 역할을 함께 확인한다.

판정 우선순위는 다음과 같다.

1. 대상 시리즈 `AGENTS.md`가 특정 템플릿을 명시한 경우
2. 대상 문서의 `type`과 `subtype`이 모두 일치하는 전용 템플릿
3. `type`이 일치하고 `subtype`이 비어 있거나 일반 범위인 템플릿
4. 문서군 전용 템플릿이 없을 때의 `설정_기본 템플릿.md`
5. 일치하는 템플릿이 없으면 `템플릿 판정 불가` 또는 `템플릿 신규 작성 필요`

예를 들어 `type: 지형`, `subtype: 대륙`은 대륙 템플릿을 사용하고, `type: 지형`, `subtype: 협곡` 또는 `지하`는 지형 템플릿을 사용한다. 제목에 `왕국`이 포함되더라도 실제 프론트매터와 역할이 도시국가라면 국가 템플릿을 임의 적용하지 않는다.

룩스테라에서 `type: 도시국가`, `subtype: 항구`는 `설정_항구 템플릿`을 적용하고, 항구가 아닌 `type: 도시국가`는 `설정_도시국가 템플릿`을 적용한다. 도시국가·항구 문서에 국가 템플릿을 적용해 필수 섹션 누락으로 판정하지 않는다.

문서의 실제 내용과 프론트매터가 충돌하면 편리한 템플릿에 맞추기 위해 `type`이나 `subtype`을 먼저 바꾸지 않는다. 분류 오류와 구조 오류를 별도 항목으로 보고하고, 분류 변경이 설정상 타당한지 먼저 판정한다.

## 템플릿 구조 추출 규칙

템플릿을 읽을 때에는 다음 요소를 분리하여 구조표를 만든다.

- 프론트매터 필드 이름과 필수 여부
- `type`과 `subtype`의 기준값
- 필수 `##` 섹션의 이름과 순서
- 템플릿 또는 시리즈 지침에서 선택으로 표시한 섹션
- 필수 `###` 또는 그 이하 제목
- `항목`, `요약`처럼 위치와 본문이 고정된 특수 섹션
- 템플릿의 안내문·자리표시자·예시 문장

템플릿이나 시리즈 지침에서 선택이라고 명시하지 않은 `##` 섹션은 기본적으로 필수로 판정한다. 안내문과 자리표시자는 실제 문서 구조를 설명하기 위한 메타 텍스트이므로 설정 문서 본문으로 복사하지 않는다.

Markdown 제목은 코드 블록, 인용 예시, 주석 안의 `#` 기호와 구분한다. 실제 제목 계층만 추출하고, 제목 단계가 건너뛰었는지 확인한다.

## 프론트매터 점검

프론트매터는 템플릿과 완전히 같은 값이 아니라 같은 **스키마와 분류 체계**를 가져야 한다. 실제 문서의 `docType`은 `setting`, `deity`, `faction_relation`, `story_design` 등 문서군에 맞게 바뀔 수 있으며, 템플릿의 `docType: template` 값을 그대로 복사해서는 안 된다.

다음 사항을 확인한다.

- YAML 시작·종료 구분자가 정상인가
- 템플릿의 필수 필드가 빠지지 않았는가
- `title`, `uuid`, `docType`, `type`, `subtype`, `region`, `status` 등의 값이 실제 문서 역할과 맞는가
- UUID가 빈 값이거나 다른 문서와 중복되지 않았는가
- 템플릿 자리표시자와 기본 예시값이 남아 있지 않은가
- 대상 시리즈 지침에서 허용하지 않은 임의 필드가 추가되지 않았는가
- 템플릿 개정으로 필드가 추가·삭제되었다면 기존 문서에 필요한 마이그레이션이 반영되었는가

프론트매터 필드 순서는 가독성을 위해 템플릿 순서를 따르는 것을 권장하지만, 의미가 동일하고 파서가 정상적으로 읽는다면 순서 차이만으로 구조 실패로 판정하지 않는다. 반면 필드 누락, 잘못된 분류, 템플릿 자리표시자 잔존은 구조 오류다.

## 상위 섹션 점검

템플릿의 필수 `##` 섹션은 이름과 순서를 그대로 유지한다. 의미가 비슷하다는 이유로 임의로 이름을 바꾸거나, 설정이 길어졌다는 이유로 새로운 `##`를 계속 추가해서는 안 된다.

다음 항목을 비교한다.

- 필수 상위 섹션 누락
- 상위 섹션 이름 변경 또는 오탈자
- 템플릿 순서와 다른 배치
- 동일 상위 섹션의 중복
- 템플릿에 없는 상위 섹션 추가
- `##`로 있어야 할 내용을 `###`로 내리거나 그 반대로 올린 제목 단계 오류
- 상위 섹션 아래의 직접 본문 없이 곧바로 하위 제목으로 내려가는 구조

템플릿에 없는 상위 섹션이 있을 때에는 먼저 그 내용이 기존 상위 섹션에 들어갈 수 있는지 판정한다. 들어갈 수 있다면 해당 범주로 이동하고 여러 문단으로 자연스럽게 이어 쓴다. 문서 고유의 세부 대상이라면 올바른 상위 섹션 아래의 `###`로 내린다. 여러 동종 문서에 반복되며 기존 템플릿 어느 곳에도 들어가지 않는 범주라면 문서를 억지로 맞추지 않고 템플릿 보강 대상으로 보고한다.

## 하위 섹션과 문단 운용

템플릿의 상위 구조를 지키는 것과 모든 문서의 하위 제목을 동일하게 만드는 것은 다르다. `###`와 `####`는 독자가 별도로 찾아볼 가치가 있는 독립 주제에만 사용한다.

하위 제목을 추가할 수 있는 대표 조건은 다음과 같다.

- 고유명이 있는 내부 지역·기관·제도·파벌·사건
- 독립적인 작동 원리나 접근 규율이 있는 대상
- 다른 문서가 직접 앵커 링크로 참조할 가능성이 높은 대상
- 이후 별도 문서로 분리될 가능성이 있는 설정 단위
- 템플릿에서 필수 하위 섹션으로 지정한 항목

한 주제가 이어지면 같은 섹션에서 세 문단, 네 문단 또는 그 이상을 작성한다. 최소 두 문단 기준을 최대 두 문단으로 오해하지 않는다. 내용이 길다는 이유만으로 제목을 만들지 않으며, 정확히 두 문단마다 새 제목을 추가하지 않는다. 짧은 내용을 두 문단으로 늘리기 위한 반복도 금지한다.

섹션 밀도와 직접 본문 분량은 별도의 문서 작성·밀도 수칙으로 점검한다. 구조 감사는 제목의 역할과 배치가 맞는지를 판정하고, 밀도 감사는 각 제목 아래 내용이 충분한지를 판정한다.

## 내용 배치 점검

제목 목록이 같아도 내용이 잘못된 범주에 들어가 있으면 구조적으로 적합하지 않다. 각 문단이 해당 상위 섹션의 질문에 답하는지 확인한다.

예를 들어 대륙 문서에서는 다음과 같이 판정한다.

- 기후·용성·자연 순환 → `지형·기후 골격`
- 종족·용종·외부 정착권 → `생활권 지도`
- 개별 숲·협곡·화산·수정핵 → `핵심 지형 요소`
- 강·호수·지하수·수원 → `수계·물길`
- 부족·탐사 연맹·공방 산업 → `문명권 구조`
- 사냥권·성지·국경·영역 → `권위권·경계`
- 계절로·관문·완충지·길잡이 → `이동·관문·완충지`
- 재해·환경 변동·외부 개입·광역 분쟁 → `대륙 규모의 위협·변수`

이 예시는 현재 대륙 템플릿의 의미를 설명하는 것이며, 템플릿 목록을 고정하기 위한 규칙이 아니다. 실제 점검에서는 대상 시리즈의 최신 템플릿과 지침을 다시 읽는다.

### 클래스 문서 점검

엘드로스의 `type: 클래스` 문서는 설정 내부에 작성자의 점검표나 작성 메모를 남기지 않는다. 아래 항목은 문서에 `## 작성 체크 항목` 같은 메타 섹션을 추가하는 기준이 아니라, 템플릿 점검자가 `기본 정보`, `설명`, `서브클래스 상세`, `비고`를 읽으며 확인하는 외부 점검 기준이다.

- 주 포지션이 `상위 담당 - 세부 태그` 형식으로 기록되었는가
- 유형이 `큰 계통 - 세부 방식` 형식으로 기록되었는가
- 서브클래스가 기본 클래스의 다른 해석으로 분리되었는가
- 다른 클래스와 겹치는 능력은 원천 또는 운용 방식의 차이로 구분되었는가
- 사회적 역할과 운용상 약점이 함께 제시되었는가

위 기준 중 하나라도 확인되지 않으면, 구조 점검 결과에 문서 내부 메타 섹션의 누락으로 적지 않는다. 대신 해당 기준과 확인 위치, 보강이 필요한 본문 범주를 보고한다.

## 항목과 요약 점검

템플릿에 `## 항목`과 `## 요약`이 있으면 두 섹션은 필수 구조로 취급한다.

- `## 항목`은 `## 요약` 바로 앞에 둔다.
- `## 항목`의 직접 본문은 정확히 `내용`으로 유지한다.
- `## 요약`은 문서의 마지막 상위 섹션으로 둔다.
- `## 요약` 뒤에 새로운 설정 섹션을 추가하지 않는다.
- `항목`과 `요약`을 하나의 섹션으로 병합하지 않는다.

템플릿에 이 구조가 없는 문서군에는 임의로 강제하지 않는다. 적용 여부는 항상 대상 템플릿을 기준으로 판단한다.

## 구조 변경과 내용 보존

템플릿에 맞춰 문서를 재배열할 때에는 기존 내용을 삭제해서 구조를 맞추지 않는다. 수정 전에 정보 보존 목록과 이동 대응표를 작성한다.

최소한 다음을 기록한다.

- 기존 상위·하위 섹션
- 각 섹션의 핵심 사실과 고유명사
- 이동 후 들어갈 템플릿 섹션
- 병합되는 중복 설명
- 별도 문서로 분리되는 내용
- 삭제하지 않고 보류해야 할 미분류 내용
- 제목 변경으로 영향을 받는 앵커 링크

내용이 템플릿 범주와 맞지 않는다고 해서 자동 삭제하지 않는다. 기존 섹션으로 이동할 수 없고 템플릿 보강도 확정되지 않았다면 `미분류 내용`으로 보고하고 사용자의 판단을 기다린다.

## 링크와 인덱스 영향

제목 이름이나 단계가 바뀌면 해당 제목을 직접 참조하는 위키 링크의 앵커가 깨질 수 있다. 구조 수정 전후에 다음 형태를 검색한다.

```text
[[문서명#기존 제목]]
[[문서명#기존 제목|표시명]]
```

이름·분류·문서 경계가 바뀌면 관련 인덱스와 역참조 문서도 함께 점검한다. 문서 분리나 병합으로 파일이 생기거나 사라지는 경우에는 파일 링크, 앵커 링크, 인덱스 항목을 같은 작업에서 갱신한다.

## 판정 등급

구조 점검 결과는 다음 등급 중 하나로 판정한다.

- `적합`: 적용 템플릿이 명확하고 필수 프론트매터·상위 섹션·순서·특수 섹션이 일치한다.
- `조건부 적합`: 필수 구조는 일치하지만 허용된 선택 섹션, 문서 고유 하위 섹션 또는 경미한 필드 순서 차이가 있다.
- `수정 필요`: 필수 섹션 누락, 순서 오류, 잘못된 상위 섹션, 분류 불일치, 특수 섹션 오류가 있다.
- `템플릿 판정 불가`: 일치하는 템플릿이 없거나 여러 템플릿이 충돌하여 적용 기준을 확정할 수 없다.
- `템플릿 보강 필요`: 문서군에 반복되는 필수 범주가 기존 템플릿에 들어갈 수 없어 템플릿 개정이 선행되어야 한다.

경미한 표현 차이와 실제 구조 오류를 같은 수준으로 다루지 않는다. 구조 수정이 필요한 경우에는 무엇이 틀렸는지뿐 아니라 어느 템플릿의 어떤 위치로 이동해야 하는지 제시한다.

## 점검 모드와 수정 모드

사용자가 `점검`, `분석`, `현황 파악`만 요청했다면 문서를 즉시 수정하지 않는다. 적용 템플릿, 현재 구조, 차이점, 권장 구조와 링크 영향을 먼저 보고한다.

사용자가 `수정`, `적용`, `개편`, `이대로 진행`을 명시하면 보존 목록과 전후 구조표를 만든 뒤 로컬 수정본을 작성한다. Google Drive 원본에는 직접 반영하지 않고 실제 경로를 재현한 ZIP으로 제공한다.

## 실행 절차

1. 대상 시리즈와 문서군을 확인한다.
2. 설정 루트와 대상 시리즈의 `AGENTS.md`를 읽는다.
3. 같은 시리즈의 최신 템플릿을 수집한다.
4. 프론트매터와 실제 역할로 적용 템플릿을 판정한다.
5. 템플릿의 필수 필드와 제목 트리를 추출한다.
6. 대상 문서의 필드와 제목 트리를 추출한다.
7. 프론트매터·상위 제목·순서·단계·특수 섹션을 비교한다.
8. 각 문단이 올바른 상위 범주에 배치되었는지 확인한다.
9. 점검 모드에서는 전후 분석안만 제시한다.
10. 수정 모드에서는 정보 보존 목록과 이동 대응표를 만든다.
11. 문서를 재배열하고 필요한 앵커·역참조·인덱스를 갱신한다.
12. 구조 수정 뒤 밀도·문체·내용 보존 점검을 별도로 수행한다.
13. 최종 구조표와 검증 결과를 보고한다.

## 출력 형식

구조 점검 결과에는 최소한 다음 내용을 포함한다.

```text
대상 문서:
적용 템플릿:
판정 등급:

프론트매터 차이:
- ...

현재 상위 구조:
- ...

템플릿 기준 구조:
- ...

구조 문제:
- 위치 / 문제 / 권장 조치

링크·인덱스 영향:
- ...

권장 수정 후 구조:
- ...
```

여러 문서를 일괄 점검할 때에는 먼저 `대상 문서 → 적용 템플릿 → 판정 등급` 대응표를 만들고, 판정 불가 문서를 별도 목록으로 분리한다. 한 템플릿을 모든 문서에 일괄 적용하지 않는다.

## 금지 사항

- 파일명이나 제목에 포함된 단어만으로 템플릿을 확정하지 않는다.
- 다른 시리즈의 템플릿을 자동으로 가져와 적용하지 않는다.
- 현재 템플릿 목록을 프롬프트에 고정하고 신규 템플릿을 무시하지 않는다.
- 문서를 편리한 템플릿에 맞추기 위해 `type`과 `subtype`을 임의 변경하지 않는다.
- 필수 상위 섹션 누락을 비슷한 이름의 다른 섹션으로 통과시키지 않는다.
- 문단 수를 맞추기 위해 제목을 늘리지 않는다.
- 두 문단 기준을 최대 두 문단으로 해석하지 않는다.
- 템플릿에 맞지 않는 내용을 근거 없이 삭제하지 않는다.
- 문서 고유 하위 섹션까지 템플릿과 완전히 동일하게 만들지 않는다.
- 구조 점검만으로 문체·밀도·설정 정합성까지 완료했다고 판정하지 않는다.
- 템플릿의 안내문과 자리표시자를 설정 본문에 남기지 않는다.

## 완료 체크리스트

- 적용 템플릿을 현재 설정 루트에서 직접 확인했는가
- 프론트매터와 문서의 실제 역할이 일치하는가
- 필수 `##` 제목의 이름과 순서가 템플릿과 일치하는가
- 선택 섹션과 필수 섹션을 구분했는가
- 템플릿에 없는 상위 섹션의 처리 근거가 있는가
- 문서 고유 하위 섹션이 올바른 상위 섹션 아래에 있는가
- 최소 두 문단을 최대 두 문단으로 오해하지 않았는가
- `항목`과 `요약`의 위치와 본문이 템플릿 기준에 맞는가
- 구조 변경 전후의 정보 보존 목록을 작성했는가
- 제목 변경에 따른 앵커 링크와 인덱스 영향을 확인했는가
- 구조 점검 뒤 밀도·문체·정합성 점검을 별도로 수행했는가
- 점검 결과와 수정 결과를 구분해 보고했는가
