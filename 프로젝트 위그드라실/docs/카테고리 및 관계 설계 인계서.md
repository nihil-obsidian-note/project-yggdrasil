# 카테고리 및 관계 설계 인계서

> 목적: 다른 GPT 대화에서 프로젝트 위그드라실의 문서 이관 설계를 중단 없이 이어가기 위한 현재 상태 요약이다.
>
> 상태: 카테고리 기준은 확정되었고, 관계 설계는 검토용 초안이다. 실제 문서 매핑과 테이블 구현은 아직 시작하지 않았다.

## 1. 이번 정리를 시작한 이유

기존 Markdown 문서는 `type`, `subtype`, 문서 폴더, `주요`, `일반` 값이 서로 다른 성격의 정보를 함께 담고 있었다. 이를 그대로 데이터베이스에 옮기면 문서 종류, 설정 중요도, 세계관 분류, 문서 용도가 뒤섞인다.

따라서 먼저 문서가 무엇에 관한 문서인지를 일관된 카테고리로 다시 정리했다. 그 다음에는 문서 링크만으로는 인물의 소속, 도시의 국가 귀속, 아이템의 소유자, 지역에 전해지는 설화처럼 의미 있는 사실을 검색·역추적할 수 없으므로, 방향과 의미를 가진 관계를 새로 설계하려 한다.

## 2. 확정된 문서 모델 방향

- 이관 대상은 `설정`, `신격`, `비밀 설정`이다.
- 세 문서군은 모두 하나의 `documents` 모델에 들어간다. `docType`은 사용하지 않는다.
- 비밀 설정은 문서 유형이 아니라 공개 범위 컬럼으로 제어한다.
- `importance`는 문서 관리·열람 중요도 컬럼이다.
- 문서 하나는 카테고리 하나만 선택한다. 복수 성격, 속성, 상태, 위계는 태그와 관계로 표현한다.
- `스토리 설계`, `설정 정비`, 템플릿, 지침, 라이브러리, 인덱스는 이번 이관 대상이 아니다.

## 3. 카테고리를 먼저 정리한 이유와 결과

카테고리는 검색·메뉴·문서 목록에서 문서의 기본 정체성을 판정하는 기준이다. 그래서 `일반`, `기타`, 빈값처럼 분류력이 없는 값을 노드로 만들지 않고, 문서를 부모 카테고리에 직접 연결한다.

- 카테고리는 월드별 독립 데이터다. 같은 이름이라도 월드가 다르면 별도 레코드가 된다.
- 하위 카테고리 전용 테이블은 만들지 않는다. `categories.parent_category_id`로 계층을 만든다.
- 메인 카테고리는 개념, 신격, 국가, 도시, 단체, 종족, 인물, 아이템, 사건, 설화, 클래스, 지형, 용종이다.
- 클래스는 엘드로스 한정이다.
- 용종 개념 문서는 `개념`에 두고, 개별 용종 도감 문서는 `용종`과 계통 하위 카테고리에 둔다.

확정한 전체 매핑과 기존 메타데이터 이관 규칙은 다음 문서가 정본이다.

- [카테고리 이관 정리](../작업%20문서/프로젝트%20위그드라실%20카테고리%20및%20서브카테고리%20이관%20정리.md)

## 4. 관계를 새로 확립하려는 이유

문서 사이의 단순 링크는 연결 여부만 표현한다. 아래처럼 설정 사실 자체가 필요한 경우에는 구조화된 관계가 필요하다.

```text
인물 → 소속 → 단체
인물 → 출신 → 국가·도시·지역
도시·지형 → 위치함 → 국가·상위 지역
아이템 → 소유됨 → 인물·단체·국가
지역 → 전승함 → 설화
국가·단체 → 동맹·견제·적대 → 국가·단체
```

관계는 하나의 사실을 한 번만 저장하고, 대상 문서에서는 역관계로 조회한다. 예를 들어 인물의 `소속` 관계는 단체 문서에서 `소속 인물`로 보인다. 대칭 관계와 방향 관계를 구분하고, 관계 자체에 공개 범위·기간·설명·근거를 둘 계획이다.

현재 초안은 관계 유형 후보, 관계별 방향과 역표시, 기존 세력 관계 문서의 이관 방향, 검토할 쟁점을 정리한 단계다. 아직 확정된 데이터베이스 설계가 아니다.

- [문서 관계 설계 초안](../작업%20문서/프로젝트%20위그드라실%20문서%20관계%20설계%20초안.md)

## 5. 다음 대화에서 이어갈 권장 순서

1. 관계 초안을 검토하고 실제로 유지할 관계 유형과 명칭을 확정한다.
2. 관계 유형과 관계 레코드의 테이블 구조, 태그·공개 범위·기간·근거의 저장 방식을 결정한다.
3. 확정된 카테고리 기준으로 현재 이관 대상 문서를 하나씩 매핑한다.
4. 이후에만 실제 데이터 이관과 애플리케이션 구현을 시작한다.

카테고리 구조 자체를 다시 바꿀 필요가 생기면, 먼저 카테고리 이관 정리 문서를 수정한 뒤 문서 매핑을 진행한다. 관계는 이 초안을 정답으로 전제하지 말고, 다음 대화에서 세계관 활용 방식과 조회 화면 요구를 기준으로 재검토한다.

## 6. 문서 위치 원칙

이 문서는 기존 인계 이력으로 `docs/`에 보존한다. 이후 모든 시리즈의 신규 작업 기록은 중앙 `프로젝트 위그드라실/작업 문서/`에서 관리한다.

- 모든 신규 작업 기록: `프로젝트 위그드라실/작업 문서/`
- 설정 정본: `프로젝트 위그드라실/위그드라실/`, `프로젝트 위그드라실/룩스테라/`, `프로젝트 위그드라실/엘드로스/`
