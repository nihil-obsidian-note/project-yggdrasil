# 프로젝트 위그드라실 문서 메타데이터 표준 설계

## 목표

`프로젝트 위그드라실` 원본 마크다운 문서의 YAML 프론트매터를 앱 친화적으로 표준화한다. 이번 설계의 핵심은 모든 대상 문서에 `uuid`를 영구 식별자로 추가하고, `thumbnail`을 일관된 방식으로 보강하며, 기존 `type`/`subtype`/`region` 및 `deity` 계열 메타를 안정적으로 검증 가능한 형태로 고정하는 것이다.

## 범위

- 대상
  - `룩스테라`
  - `엘드로스`
  - `위그드라실`
- 기준
  - 원본 문서만 대상으로 본다.
- 제외
  - 구버전 보관 폴더
  - 앱 코드 변경

## 핵심 결정

### 1. 공통 필수 메타데이터

모든 대상 문서는 아래 공통 키를 가진다.

```yaml
uuid: ""
title: ""
docType: ""
thumbnail: ""
status: ""
created_at: ""
updated_at: ""
```

- `uuid`
  - 문서의 영구 식별자다.
  - 제목, 파일명, 링크가 바뀌어도 유지되어야 한다.
  - 이미 값이 있으면 유지하고, 없으면 새로 생성한다.
- `title`
  - 표시용 제목이다.
  - 기존 `이름` 키는 `title`로 통일하는 방향을 기본값으로 삼는다.
- `docType`
  - 앱과 후속 파이프라인에서 문서군을 판별하는 값이다.
  - 최소한 `setting`, `deity`는 반드시 식별 가능해야 한다.
- `thumbnail`
  - 대표 이미지 경로 또는 식별자다.
  - 값이 없으면 빈 문자열 `''`을 사용한다.
  - 앱의 기본 썸네일 대체는 앱 레이어 책임으로 둔다.
- `status`, `created_at`, `updated_at`
  - 기존 운영 기준을 유지한다.

### 2. 문서 타입별 메타데이터

#### `deity`

```yaml
rank: ""
alignment: ""
domain: []
portfolio: []
pantheon: false
cheongyeon_pantheon: false
```

#### `setting`

```yaml
type: ""
subtype: ""
region: ""
```

### 3. `docType` 분류 원칙

이번 단계의 최소 보장값은 아래와 같다.

- `deity`: 신격 문서
- `setting`: 설정 문서

후속 확장 후보는 아래와 같지만 이번 작업의 1차 필수 범위는 아니다.

- `secret_setting`
- `relation`
- `story_design`
- `maintenance`
- `template`

단, 실제 스크립트 설계 시에는 문서군 판별을 위해 위 값을 함께 다루는 편이 안전하다.

- 실제 권역 체계가 정리된 뒤 후보군을 확장한다.

## 적용 원칙

### 본문 보존

- 기존 본문은 수정하지 않는다.
- 이번 작업은 프론트매터 계층만 다룬다.

### 재실행 안정성

- 변환 스크립트는 여러 번 실행되어도 같은 결과를 내야 한다.
- 이미 존재하는 `uuid`는 절대 바꾸지 않는다.
- 이미 존재하는 `thumbnail`은 덮어쓰지 않는다.

### 빈 값 처리

- `thumbnail` 미존재 시 `thumbnail: ''`
- 조건부 필드가 비어도 되는 경우는 빈 문자열 또는 빈 배열 정책을 명시적으로 따른다.

## 예상 이슈

### 1. `이름`과 `title` 혼재

현재 저장소에는 `이름:`와 `title:`가 혼재한다. 이번 작업은 공통 키를 `title`로 통일하는 계기가 되어야 한다.

### 2. 문서군별 스키마 불균일

- `비밀 설정`
- `설정`
- `신격`
- `세력 관계`
- `스토리 설계`
- `설정 정비`

각 문서군은 이미 서로 다른 프론트매터 키를 사용하므로, 단일 일괄 치환보다 문서군별 규칙 테이블이 필요하다.

### 3. 썸네일 소스 부재

이미지 자산이 연결되지 않은 문서가 다수일 수 있다. 이 경우 이번 단계에서는 빈 문자열을 표준값으로 넣고, 이미지 매핑은 후속 작업으로 분리한다.

## 권장 구현 전략

### 1단계: 스키마 정규화

- `이름`을 `title`로 통일
- `uuid`, `thumbnail`, `docType`를 공통 주입
- 기존 필수 메타 유지

### 2단계: 타입 검증 체계 구축

- `setting.type`
- `setting.subtype`
- `setting.region`
- `deity.rank`
- `deity.alignment`

허용값 검증 로직을 스크립트로 만든다.

### 3단계: 전체 적용 전 검증

- `uuid` 중복 검사
- 누락 키 검사
- 본문 변경 여부 표본 점검
- 대표 문서 샘플 확인

## 완료 기준

- 대상 원본 문서 전부에 `uuid`가 존재한다.
- 대상 원본 문서 전부에 `thumbnail` 키가 존재한다.
- `deity` 및 `setting` 문서는 타입별 필수 메타를 유지한다.
- `AGENTS.md` 기준 타입/서브타입 체계와 실제 문서 메타가 충돌하지 않는다.
- 재실행 시 `uuid`가 바뀌지 않는다.

## 이번 단계에서 문서화해야 할 후속 작업

- `AGENTS.md` 운영 규칙에 `uuid`와 `thumbnail`을 추가
- 변환 스크립트 작성
- 검증 스크립트 작성
- 템플릿 문서 메타도 같은 표준으로 동기화할지 결정
